# Noctaxis 0.2 release notes

## Logs and diagnostics

- **Export Logs.** Settings → Diagnostics now appears for everyone, with an **Export Logs** button. It saves the
  application logs and basic diagnostic information (Noctaxis version, operating system, .NET runtime) to a ZIP
  file you choose, ready to attach to a bug report. Nothing is uploaded. The archive may contain file paths or
  location information, so review it before sharing. It never includes your settings, saved locations, equipment,
  supporter licence or caches. The terrain developer tools stay hidden unless Noctaxis is started with
  `NOCTAXIS_DIAGNOSTICS=1`.
- **Log history is kept by day.** 0.1 kept only the ten newest log files, so a few launches in a row could remove
  the logs of earlier days. 0.2 keeps one log per session and compresses each earlier day into a single archive
  (`Noctaxis-2026-10-17.zip`). It keeps the ten most recent days on which Noctaxis was used, however many times it
  was started on each. Today's logs stay uncompressed and don't count towards the ten.
- A session that runs past midnight continues in a new file for the new day. Changes of date, daylight-saving and
  clock changes never delete logs.
- Existing 0.1 logs (`noctaxis-<date>-<time>-<pid>.log`) are archived by date at the first 0.2 start.
- Archiving checks each archive before removing the logs it holds. A failure keeps the logs and is recorded in the
  current log, and Noctaxis carries on normally.

Details: [Logs and diagnostics export](../logging.md).
